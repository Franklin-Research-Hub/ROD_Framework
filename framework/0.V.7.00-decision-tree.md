DECISION TREE LOGIC IN TEXT FORMAT

1. START: Proposal submitted

2. Identify proposer role
   - If Victoria Love Franklin (Creator) → Go to step 3
   - If Jack Brown or Karen Johnson → Route to FULL CHAIN (Route A)
   - If other staff/department → Route to FULL CHAIN (Route A)
   - If unclear → Ask proposer to identify role

3. Threat assessment (Creator proposals only)
   - Review 8-point threat checklist
   - If ANY threats checked → Route to FULL CHAIN (Route A)
   - If NO threats checked → Go to step 4

4. Terrell discretion (Creator-only pathway)
   - Terrell reviews proposal
   - Terrell decides if Metro IT review is necessary
   - If Metro IT review needed → Route to appropriate review (Route C)
   - If Metro IT review NOT needed → Route to CREATOR-ONLY (Route B)

5. Final approval
   - Route A: Approvals by Jack → Karen → Terrell
   - Route B: Approval by Terrell only
   - Route C: As determined by Terrell

6. Completion
   - Archive approval form with proposal
   - Proposal proceeds to next implementation layer upon approval


USING THIS DECISION TREE

- Print and display this decision tree visually
- Use logic in approval forms (radio button selections)
- Train reviewers on each decision point
- Refer back to this tree when routing confusion arises
- Document which decision point applies to each proposal
