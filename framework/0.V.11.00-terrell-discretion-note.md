TERRELL WILSON DISCRETION NOTE

Metro IT Review Authority & Decision Framework

AUTHORITY STATEMENT

Terrell Wilson (Deputy Register Information Technology) holds final decision-making
authority over whether Metro IT review is required for framework proposals under
this approval system.

Metro IT review is NOT automatically required for every proposal. Metro IT review
is triggered only at Terrell Wilson's discretion based on the specific risks,
compliance needs, or technical concerns presented by each proposal.

═══════════════════════════════════════════════════════════════════════════════

DISCRETION AUTHORITY

Terrell Wilson determines Metro IT review is required when a proposal:

  • Involves public records handling or retention
  • Requires accessibility (ADA/WCAG) compliance verification
  • Involves website or public-facing digital content
  • Handles sensitive or restricted data
  • Creates potential IT security, privacy, or compliance risks
  • Involves external system integration or platform configuration
  • Requires technical validation or architectural review
  • Presents policy or governance uncertainty requiring expert review
  • Is escalated for higher-level review
  • Involves department-wide or city-wide systems

Terrell Wilson determines Metro IT review is NOT required when:

  • Proposal is framework documentation, architecture, or design-only
  • Proposal involves no data handling, retention, or system integration
  • Proposal has no accessibility or compliance implications
  • Proposal is internal governance or organizational structure
  • Proposal is business process, policy, or procedural (no IT component)
  • Proposal has been reviewed and presents no identified risks
  • Proposal is a preliminary concept or architectural proposal with no implementation phase

═══════════════════════════════════════════════════════════════════════════════

DISCRETION PROCESS

When a proposal reaches Terrell for review:

1. Terrell reviews the proposal and threat assessment

2. Terrell asks: "Does this proposal create a potential Metro IT policy,
   technical, security, compliance, or governance concern?"

3. If YES:
   → Terrell determines appropriate Metro IT review level
   → Proposal may be escalated to full Metro IT review
   → Proposal may require conditional approval pending technical review
   → Proposal may be returned for technical revision

4. If NO:
   → Terrell may approve proposal under Creator-Only path (if creator)
   → Terrell may approve proposal without external Metro IT review
   → Proposal proceeds to next implementation layer

5. Terrell documents the discretion decision on the approval form

═══════════════════════════════════════════════════════════════════════════════

DECISION DOCUMENTATION

On every approval form, Terrell indicates:

  [ ] Metro IT review is NOT required
      Reason: ________________________________________________________________

  [ ] Metro IT review IS required
      Reason: ________________________________________________________________
      Escalation path: _______________________________________________________

  [ ] Metro IT review is CONDITIONAL
      Condition: _____________________________________________________________
      Review trigger: ________________________________________________________

This documentation creates an audit trail and ensures consistency across
all proposals.

═══════════════════════════════════════════════════════════════════════════════

GUIDELINES FOR DISCRETION

Terrell should consider:

  ✓ Scope: Is this proposal limited to internal framework or does it have
    external/public-facing implications?

  ✓ Data: Does this proposal involve personal data, records, or sensitive
    information?

  ✓ Compliance: Does this proposal involve public records, accessibility,
    or regulatory requirements?

  ✓ Integration: Does this proposal require system integration, platform
    configuration, or technical implementation?

  ✓ Precedent: Have similar proposals been reviewed? What was the outcome?

  ✓ Risk: What is the consequence if this proposal violates a Metro IT
    policy or technical requirement?

  ✓ Timeline: Does the proposal timeline allow for external Metro IT review
    if needed?

═══════════════════════════════════════════════════════════════════════════════

CREATOR PROPOSAL FAST-TRACK

For proposals from Victoria Love Franklin (Framework Creator) with no
identified threats:

  • Creator proposals are typically lower-risk framework documentation
  • Creator has authority and knowledge of governance requirements
  • Metro IT review may often be waived for creator proposals unless
    technical or policy concerns are identified
  • Terrell may approve creator proposals quickly if no Metro IT review
    is needed
  • Timeline: 2-3 business days typical for creator proposals

However:

  ⚠ Even creator proposals may require Metro IT review if:
    - Technical implementation is involved
    - Public-facing website content is proposed
    - Data handling or records are involved
    - Accessibility compliance is required
    - Terrell identifies any policy or compliance concern

═══════════════════════════════════════════════════════════════════════════════

ESCALATION TRIGGERS

Terrell should escalate to Metro IT when:

  🚩 Proposal involves website publishing or public digital content
  🚩 Proposal involves records retention or public records access
  🚩 Proposal involves accessibility (ADA/WCAG) compliance questions
  🚩 Proposal involves data security, privacy, or IT security concerns
  🚩 Proposal requires platform, configuration, or system review
  🚩 Proposal creates uncertainty about policy compliance
  🚩 Proposal has significant operational or compliance implications
  🚩 Multiple approvers have concerns about technical aspects

═══════════════════════════════════════════════════════════════════════════════

APPROVAL WITHOUT METRO IT REVIEW

Terrell may approve proposals WITHOUT external Metro IT review when:

  ✓ Proposal is framework documentation or governance-only
  ✓ No external or public-facing implementation is involved
  ✓ No data handling or records retention is involved
  ✓ No accessibility compliance questions exist
  ✓ No IT security or platform integration is involved
  ✓ Terrell is confident in the proposal from a policy perspective
  ✓ Creator has full authority and knowledge of requirements
  ✓ Proposal will be reviewed for technical details in later phases

Example: Website homepage architecture framework proposed by Victoria Love
Franklin as documentation may be approved by Terrell without Metro IT review
if it contains no data handling, security, or compliance concerns.

═══════════════════════════════════════════════════════════════════════════════

APPROVAL AUTHORITY STATEMENT

Terrell Wilson, as Deputy Register Information Technology, holds authority to:

  ✓ Approve or reject any framework proposal
  ✓ Approve proposals without external Metro IT review
  ✓ Determine when Metro IT review is necessary
  ✓ Escalate proposals for higher-level review
  ✓ Place conditions on approval
  ✓ Request revision or additional information
  ✓ Make final Metro IT governance decisions for this framework

This authority is granted to enable efficient approval of low-risk proposals
while maintaining full governance authority over Metro IT compliance.
