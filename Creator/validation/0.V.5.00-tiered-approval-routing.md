------------------------------------------------------------

This node establishes the routing logic for framework proposals to determine which approval chain is required.

METRO IT REVIEW NOTE

Metro IT review is not automatically required for every proposal.

Metro IT review is triggered only when Terrell Wilson determines that the proposal may create a policy, security, records, privacy, accessibility, or compliance risk.

If Terrell determines no Metro IT review is needed, the proposal may proceed through the creator-only or streamlined path.

APPROVAL ROUTING DECISION TREE

┌─────────────────────────────────────────────────────────────┐
│ STEP 1: IDENTIFY PROPOSER ROLE                              │
└─────────────────────────────────────────────────────────────┘

Question: Who is submitting this proposal?

[ ] Framework Creator (Victoria Love Franklin)
    → Go to STEP 2 (Creator pathway)

[ ] Department Leadership (Jack Brown, Karen Johnson)
    → Go to FULL CHAIN (Jack → Karen → Terrell)

[ ] Other Staff / Department
    → Go to FULL CHAIN (Jack → Karen → Terrell)

[ ] Metro IT / Technical Review Required by Terrell
    → Go to TERRELL DISCRETION PATH


┌─────────────────────────────────────────────────────────────┐
│ STEP 2: CREATOR PATHWAY - ASSESS THREAT LEVEL              │
└─────────────────────────────────────────────────────────────┘

If proposer is Victoria Love Franklin (Framework Creator):

Question: Does this proposal create any of these threats?

[ ] Violates Metro IT policy
[ ] Violates public records policy
[ ] Requires records retention compliance
[ ] Requires accessibility compliance review
[ ] Handles sensitive or restricted data
[ ] Impacts IT security or data handling
[ ] Requires department operational sign-off
[ ] Requires department governance approval

If ANY boxes checked above:
    → FULL CHAIN APPROVAL (Jack → Karen → Terrell)
    → Use 0.V.2.00 (Threat Assessment Template)
    → Route to Jack Brown first

If NO boxes checked above:
    → CREATOR-ONLY / TERRELL-ONLY APPROVAL
    → Use 0.V.6.00 (Creator-Only Approval Path)
    → Route directly to Terrell Wilson
    → No Jack or Karen approval needed
    → Metro IT review is optional and may be determined by Terrell


┌─────────────────────────────────────────────────────────────┐
│ STEP 3: TERRELL DISCRETION PATH                             │
└─────────────────────────────────────────────────────────────┘

If Terrell determines that Metro IT review is needed, the proposal may be routed as follows:

[ ] Terrell reviews the proposal and decides if Metro IT oversight is required
[ ] If Metro IT review is required, Terrell determines the appropriate path
[ ] If Metro IT review is not required, proposal may continue under Creator-Only or streamlined process

Examples of proposals that may require Terrell discretion:

- data handling or records retention concerns
- external publication or website content issues
- public-facing web implementation concerns
- accessibility and compliance concerns
- security or platform configuration concerns


┌─────────────────────────────────────────────────────────────┐
│ ROUTING SUMMARY                                             │
└─────────────────────────────────────────────────────────────┘

ROUTE A: FULL APPROVAL CHAIN (Jack → Karen → Terrell)
  Proposer: Any non-creator
  Threat Level: Any (LOW/MEDIUM/HIGH)
  Process: Use 0.V.2.00 (Threat Assessment Template)
  Checklist: Use 0.V.3.00 (Validation Checklist)
  Approvals Required: All 3
  Metro IT: Required when designated by Terrell

ROUTE B: CREATOR-ONLY / TERRELL-ONLY APPROVAL
  Proposer: Victoria Love Franklin (Creator)
  Threat Level: NONE (no threats identified)
  Process: Use 0.V.6.00 (Creator-Only Approval Path)
  Approvals Required: Terrell Wilson only
  Metro IT: Optional based on Terrell's discretion
  Timeline: 2-3 business days typical

ROUTE C: TERRELL DISCRETION REVIEW
  Proposer: Any
  Trigger: Terrell determines a policy, technical, or compliance review is needed
  Process: Terrell decides final review path
  Approvals Required: Based on review determination
  Metro IT: Up to Terrell discretion

ROUTE D: ESCALATED APPROVAL
  Proposer: Any
  Threat Level: HIGH or unresolved
  Process: Identify additional stakeholders
  Approvals Required: Jack → Karen → Terrell + escalation
  Metro IT: Required as appropriate


┌─────────────────────────────────────────────────────────────┐
│ IMPLEMENTATION GUIDANCE                                     │
└─────────────────────────────────────────────────────────────┘

1. Complete the initial routing decision tree
2. Identify which route applies (A, B, C, or D)
3. Use the appropriate approval form/template for that route
4. Submit to the first approver in the chain
5. Each approver completes their section and routes to the next
6. Archive the completed form with the approval node

For Creator Proposals (Route B):
  - Use 0.V.6.00 (Creator-Only Approval Path)
  - Complete minimal documentation
  - Submit directly to Terrell Wilson
  - Terrell reviews for Metro IT compliance only when needed
  - Upon approval, proposal may proceed to implementation

For Non-Creator Proposals (Route A):
  - Use Full Chain approval
  - If Metro IT review is not required, Terrell may still be the final reviewer if policy indicates it
  - If Metro IT review is required, Terrell may request additional technical review

------------------------------------------------------------

Use this routing system to determine the correct approval path for all framework proposals while keeping Metro IT review flexible and controlled by Terrell Wilson.
