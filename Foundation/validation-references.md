# Validation References

## 1. Purpose
This document provides manual consistency checks for Foundation changes and their effects on current repository navigation.

## 2. Reference Authorities
- [Master tree](../MASTER-TREE-BRANCH.md) — structural authority.
- [TOC](../TABLE-OF-CONTENTS.md) — matching navigation list.
- [Working definitions](../INDEX-METADATA-DEFINITIONS.md) and [metadata model](metadata-model.md) — terms and labeling.
- [Governance](governance.md) and [contribution rules](../CONTRIBUTING.md) — approval and workflow.
- [Local tree](tree-branch.md) — Foundation scope.
- [Creator index](../Creator/INDEX.md) — creator record registration.

## 3. Validation Checklist
| Check | Criterion |
|---|---|
| Naming and links | Referenced files exist; relative links resolve from the containing document |
| Navigation | TOC lists exactly the master navigation files in the same order |
| Tree scope | Master tree shows structural navigation; local trees show their branch contents |
| Roles | Foundation rules do not duplicate root authority or creator record content |
| Dependency | Creator depends on Foundation, never the reverse for structural validity |
| Numbering | Each structured document uses consecutive local sections starting at 1 |
| Identity | Anchor identifiers, section numbers, layers, and versions remain distinct |
| Records | Creator records remain branch-owned and registered through their index |
| Governance | Changes receive required approval and update affected documents together |
| Status and rights | Working status is explicit; notice and license remain distinct and aligned |

## 4. Validation Timing
Check whenever a file is added, renamed, moved, removed, or substantially edited. Local record enumeration is not a mismatch merely because master navigation omits records.

## 5. Status
Active-working validation baseline. These checks establish documentation consistency, not external certification or a grant of usage rights.
